# Design Patterns Inventory — Progressive Minie Shop

Living architectural catalog of every software and React design pattern actually implemented across the **Progressive Minie Shop** monorepo (`apps/storefront`, `apps/api`, and `packages/*`).

> **Maintenance Rule (Keep Updated As We Go):**
> Whenever a new design pattern is introduced, refactored, made consistent across modules, or retired during any phase or PR, update this document in the same change set. Only list patterns backed by concrete code in the repository; clearly distinguish deliberate patterns from ad-hoc implementations and intentional absences.

## 1. Frontend & React Design Patterns (`apps/storefront`)

| Pattern | Status | Location | Problem Solved | Assessment | Trade-offs |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Headless UI / Prop Getters** | Deliberate | `apps/storefront/src/hooks/useCombobox.ts`, `apps/storefront/src/components/SearchBar/SearchBar.tsx` | Encapsulates WAI-ARIA APG combobox keyboard navigation, IME guard, outside pointer dismiss, and `aria-activedescendant` focus without coupling to styling or external deps (`ADR-0020`). | **Strong & Justified.** Cleanest primitive hook in the storefront; verified with `vitest-axe`. Gap: `Dropdown.tsx` does not yet mirror this pattern and lacks arrow-key navigation. | Team owns APG edge-case maintenance; should serve as a benchmark when defining Phase 8 Design System primitives. |
| **Provider / Dependency Injection** | Deliberate | `apps/storefront/src/context/ProductRepositoryProvider.tsx`, `apps/storefront/src/hooks/useProductRepository.ts`, `apps/storefront/src/i18n/I18nProvider.tsx` | Injects `ProductRepository` (`HttpProductRepository` in runtime, `MockProductRepository` in tests) and reactive `en` / `pt-BR` locale without prop drilling. | **Justified.** Enables fast zero-network integration suites. Minor leak: `productRepositoryContext.ts` imports concrete `HttpProductRepository` directly. | `I18nProvider` reads `window.localStorage` in initial `useState`, which will require SSR-safe hydration if migrating to Next.js. |
| **Repository Pattern** | Deliberate | `apps/storefront/src/domain/repositories/ProductRepository.ts`, `apps/storefront/src/infrastructure/repositories/HttpProductRepository.ts`, `MockProductRepository.ts` | Decouples UI/hooks from `fetch` and gives tests an in-memory behavioral twin verified by `productRepositoryContract.test.ts`. | **Mixed at current scale.** Works well for catalog reads, but has grown into a 12-method god interface spanning 5 domains plus HTTP `URLSearchParams` encoding. | `MockProductRepository` (918 LOC) carries maintenance overhead; should split by domain when Checkout/Identity UI arrives. |
| **Adapter Pattern (Search Client)** | Deliberate | `apps/storefront/src/infrastructure/search/instantSearchAdapter.ts`, `apps/storefront/src/pages/SearchResultsPage/SearchResultsPage.tsx` | Adapts `ProductRepository.searchProducts` (`GET /search`) to the `SearchClient` contract expected by `react-instantsearch` without talking directly to Meilisearch (`ADR-0019`). | **Under review.** Correctly isolates InstantSearch to a lazy chunk, but `/search` uses zero InstantSearch facet/refinement widgets while requiring 257 LOC of abort/superseding deferral logic. | High adapter complexity relative to features currently used; re-evaluate vs. `useInfiniteQuery` if InstantSearch widgets are not adopted. |
| **Facade Hooks + Granular Subscriptions** | Deliberate *(inconsistent)* | `apps/storefront/src/hooks/useCart.ts`, `useCurrency.ts`, `useFavorites.ts`, `useProducts.ts`, `useRecommendations.ts`, `useSearch.ts` | Hides Redux/TanStack Query wiring behind domain-oriented hooks and isolates component re-renders (`useCartBadge`, `useCartItemState`, `useCartActions`). | **Strong in `CartPage` & `Navbar`, broken on catalog/search surfaces.** `ProductCard`, `ProductListingPage`, `ProductDetailPage`, and `SearchResultsPage` call coarse `useCart()` instead of `useCartActions()`, subscribing every card to full cart state. | Easy to misuse when coarse (`useCart`) and granular (`useCartActions`) hooks coexist without lint guidance. |
| **Memoized Derived State (`createSelector` + `React.memo`)** | Deliberate | `apps/storefront/src/store/selectors/cartSelectors.ts`, `apps/storefront/src/pages/CartPage/components/*` | Avoids recomputing cart subtotal/discount/shipping/total and prevents sibling re-renders while typing notes, editing quantities, or applying coupons. | **Verified & Justified.** Proven by Reselect `.recomputations()` assertions (`cartSelectors.test.ts`) and React `<Profiler>` budgets (`CartPage.profiler.test.tsx`). | Adds subcomponent boilerplate; keep strictly for high-churn interactive views like Cart. |
| **Listener Middleware Side-Effect Decoupling** | Deliberate *(inconsistent)* | `apps/storefront/src/store/index.ts`, `apps/storefront/src/store/slices/cartSlice.ts`, `apps/storefront/src/store/persistence/cartStorage.ts` | Keeps cart reducers 100% pure while persisting versioned v2 items and debounced preferences (with `pagehide` flush) to `localStorage`. | **Strong for `cartSlice`, inconsistent for `currencySlice`.** `currencySlice.ts` still reads/writes `localStorage` inside its reducer/module init, and `applyCartQuote` is missing from `cartPersistenceListener`. | Requires discipline across all slices to maintain purity and SSR safety. |
| **Optimistic UI with Concurrency Queue Projection** | Deliberate | `apps/storefront/src/hooks/useFavorites.ts` (`WeakMap<QueryClient, FavoriteChanges>` + `scope: { id: 'favorites' }`) | Eliminates optimistic rollback race conditions when users click favorite toggles rapidly across overlapping network requests. | **Smart & Justified.** Cleanly separates confirmed server state from pending toggle queue and invalidates only once the queue drains. | Module-level `WeakMap` state is non-obvious; should be guarded by a dedicated rapid-toggle unit test. |
| **Adjusting State During Render** | Deliberate | `ProductImage.tsx`, `useCombobox.ts`, `CatalogFilters.tsx`, `SearchBar.tsx`, `SearchResultsPage.tsx` | Synchronously resets derived local state when props or URL parameters change without triggering an extra `useEffect` paint cycle. | **Clean in `ProductImage`/`useCombobox`; symptomatic in `SearchResultsPage`.** Tracking 4 `prev*` states in `SearchResultsPage` compensates for InstantSearch's internal async status transitions. | Avoids effect flicker, but multi-field render-time `setState` increases cognitive load. |
| **Controlled / Uncontrolled Hybrid Inputs** | Deliberate | `Dropdown.tsx`, `CatalogFilters.tsx`, `CartItemRow.tsx` | Allows immediate local typing, debouncing, or draft validation before committing changes to URL params or Redux. | **Justified.** Note `CatalogFilters` manually duplicates `setTimeout` debouncing twice rather than reusing `useDebounce`. | Requires careful timer cleanup on external resets (e.g., Clear All or currency switch). |
| **Lazy Code Splitting + `<Suspense>`** | Deliberate *(incomplete)* | `apps/storefront/src/App.tsx` (`SearchResultsPage`), `apps/storefront/src/layouts/RootLayout/RootLayout.tsx` (`ApiDebugFab`) | Keeps `react-instantsearch` (~189 kB raw / ~52 kB gzip) and dev-only chaos UI out of initial catalog/PDP bundles. | **Effective bundle split, missing fault boundary.** Verified by Playwright bundle-split checks, but no `<ErrorBoundary>` wraps `<Suspense>`. | Chunk-load failures currently crash the SPA without recovery UI. |
| **Layout Route (`<Outlet />`) & Key-Based Reset** | Deliberate | `apps/storefront/src/App.tsx`, `RootLayout.tsx`, `ProductDetailPage.tsx` (`<PdpRecommendationsSection key={product.slug} />`) | Shares persistent chrome (`Navbar`, footer, `MiniCart`) across routes and resets latched `useInView` state on PDP-to-PDP navigation. | **Sound idiom with one semantic bug.** Four pages (`PLP`, `PDP`, `Search`, `NotFound`) render a nested `<main>` inside `RootLayout`'s `<main>`. | Clean and idiomatic once nested `<main>` tags are removed. |
| **Latched Viewport Lazy Loading (`IntersectionObserver`)** | Deliberate | `apps/storefront/src/hooks/useInView.ts`, `apps/storefront/src/pages/ProductDetailPage/components/PdpRecommendationsSection.tsx` | Defers PDP recommendation API calls until the user approaches the section (`rootMargin: '200px 0px'`), keeping initial PDP load lean (`ADR-0021`). | **Verified & Effective.** Achieves 0 pre-scroll requests and `0.0000` CLS (`docs/metrics/search-and-recommendations-ui.md`). | Requires deterministic `IntersectionObserver` stubbing in jsdom tests (`src/test/intersectionObserverMock.ts`). |
| **External Store Pub-Sub** | Ad-hoc / Superficial | `apps/storefront/src/infrastructure/http/chaos.ts`, `apps/storefront/src/components/ApiDebugFab/ApiDebugFab.tsx` | Syncs dev-only `chaos.*` `localStorage` overrides with the floating debug panel. | **Acceptable for DEV-only tool.** Manual subscriber set + `useEffect`/`useState` instead of `useSyncExternalStore`. | Not worth over-engineering; tree-shaken from production builds via `import.meta.env.DEV`. |

## 2. Backend & Distributed Systems Design Patterns (`apps/api`)

| Pattern | Status | Location | Problem Solved | Assessment | Trade-offs |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Modular Monolith with Barrel Boundaries** | Deliberate | `apps/api/src/modules/{catalog,identity,media,platform,recommendations,search}/index.ts`, `apps/api/eslint.config.mjs` | Enforces clear domain boundaries inside one deployable Node process with static `eslint-plugin-boundaries` checks (`ADR-0002`). | **Strong, with one DB loophole.** TypeScript cross-module imports strictly respect `index.ts`, but `src/database/**` is grouped into `app-shell`, letting any module import another module's Drizzle tables. | Shared deploy/runtime blast radius; needs per-schema boundary rules to seal the DB loophole. |
| **Database-per-Module Schema Isolation** | Deliberate *(1 violation)* | `apps/api/src/database/schema/{catalog,identity,inventory,media,platform,recommendations}.ts`, `apps/api/drizzle/*.sql` | Isolates persistence ownership across 6 PostgreSQL schemas inside a single PG17 instance while keeping local ACID transactions (`ADR-0006`). | **Mostly clean; 1 live violation.** `MediaService.linkProductImage` writes directly into `catalog.product_images`. Also `inventory.stock_items` and `platform.store_settings` are seeded but unused at runtime. | Maintaining read projections (`products.in_stock`) requires explicit sync discipline. |
| **Ports & Adapters (Hexagonal)** | Deliberate | `search.port.ts` → `MeilisearchAdapter`; `embedding.port.ts` → `OllamaEmbeddingProvider` / `DeterministicFakeEmbeddingProvider`; `mail-transport.ts` → `Smtp`/`Resend`/`InMemory`; `rate-limiter.ts` → `InMemoryRateLimiter`; `s3-storage.adapter.ts`; `clock.ts` | Isolates domain services from external infrastructure (Meilisearch, Ollama, SeaweedFS/S3, SMTP/Resend, system clock) so CI/tests run deterministically and providers stay swappable. | **Very Strong.** Clean NestJS DI tokens (`SEARCH_PORT`, `EMBEDDING_PROVIDER`, `MAIL_TRANSPORT_TOKEN`, `RATE_LIMITER_TOKEN`, `CLOCK_TOKEN`) enable fast test fakes without monkey-patching. | Adds interface/token wiring boilerplate; justified wherever external I/O or time is involved. |
| **Transactional Outbox + Polling Worker** | Deliberate | `apps/api/src/modules/platform/outbox.service.ts`, `outbox-events.ts`, `apps/api/src/worker/main.ts`, `worker.runner.ts` | Guarantees reliable async propagation of catalog, embedding, recommendation, and email events without dual-write loss or external brokers (`ADR-0012`). | **Production-grade, 1 atomicity bug.** Uses `FOR UPDATE SKIP LOCKED`, leases, per-consumer fan-out rows, and exponential backoff + jitter. Bug: `EmbeddingsOutboxHandler` upserts embeddings outside the transaction that enqueues `product.embedding_updated`. | Polling adds small eventual-consistency lag (`500ms` default) and requires retention cleanup (`OUTBOX_RETENTION_DAYS`). |
| **Circuit Breaker + Multi-Tier Graceful Degradation** | Deliberate | `apps/api/src/modules/search/circuit-breaker.ts`, `search.service.ts`, `apps/api/src/modules/recommendations/relations.service.ts` | Keeps storefront search and recommendations available (`HTTP 200`) even when Ollama or Meilisearch is slow or down (`ADR-0010`, `ADR-0013`). | **Strong & Tested.** Search degrades `hybrid` → `keyword` → `postgres` (3 failures / 15s open window); recommendations degrade from `pgvector` kNN to deterministic rules. | In-memory circuit breaker state is per API replica (acceptable at single-instance/small scale). |
| **TTL LRU Cache** | Deliberate | `apps/api/src/modules/search/lru-cache.ts`, `apps/api/src/modules/search/search.service.ts` | Caches query embedding vectors (`256` entries, `5 min` TTL) to avoid repeating `~2.6s` CPU Ollama inference for repeated searches. | **Well-scoped & Simple.** Zero external dependency (no Redis required). | Per-process memory cache; not shared across multiple API replicas. |
| **Content-Hash Idempotency & Deduplication** | Deliberate | `apps/api/src/modules/search/embedding-text.ts` (`computeEmbeddingContentHash`), `apps/api/src/modules/media/media.service.ts` (`checksumSha256`) | Prevents redundant embedding inference when non-indexed fields change (`ADR-0011`) and deduplicates identical uploaded media binaries. | **Effective (minor media retry edge case).** Media dedupe only short-circuits `status === 'ready'`, so retrying a `'failed'` checksum hits the unique constraint. | Changing embedding template version or model cleanly forces recomputation via hash mismatch. |
| **Zero-Downtime Shadow Index Swap** | Deliberate | `apps/api/src/modules/search/meilisearch.adapter.ts` (`reindex`) | Rebuilds the Meilisearch `products` index into a temporary index and performs an atomic `/swap-indexes` with zero search downtime. | **Verified.** Idempotency verified automatically in `pnpm search:eval` (`docs/metrics/search-relevance.md`). | Temporarily doubles Meilisearch index storage during full reindex. |
| **Advisory-Lock Job Coordination** | Deliberate | `apps/api/src/modules/identity/session.service.ts` (`pg_try_advisory_xact_lock`), `apps/api/src/worker/main.ts` | Prevents concurrent worker replicas from running overlapping `cleanupExpiredSessions()` sweeps. | **Clean & Lightweight.** Uses native PostgreSQL advisory locks without extra scheduler infrastructure. | Requires maintaining a unique numeric lock key per scheduled job. |
| **Deny-by-Default Guard + Metadata Decorators** | Deliberate | `apps/api/src/modules/identity/identity.guard.ts`, `decorators.ts`, `staff-admin.controller.ts` | Enforces dual-cookie principal resolution, Origin + HMAC CSRF protection, customer auth, and deny-by-default RBAC across `/admin/*` (`ADR-0014`). | **Strong, 1 route trap.** Reflection-based test (`staff-rbac.integration.spec.ts`) proves every `/admin/*` route declares explicit auth metadata. Gap: read-only `POST /pricing/quote` lacks `@SkipCsrf()` and will fail once customer cookies are active on storefront. | Global `APP_GUARD` makes opt-out explicit (`@SkipCsrf`, `@PublicAdminRoute`), which is safer than opt-in. |
| **Global Exception Filter + Domain Error Factory** | Deliberate | `apps/api/src/common/global-exception.filter.ts`, `apps/api/src/common/errors.ts`, `apps/api/src/common/parse-response.ts` | Normalizes all API errors into `{ error: { code, message, details?, requestId } }` (`ADR-0008`). | **Consistent, 1 5xx leak bug.** `GlobalExceptionFilter` masks `HttpException` 5xx but skips masking and `request.log.error` for `AppHttpError(500)` thrown by `parseOutput`. | Centralizes error formatting cleanly once the 5xx `AppHttpError` branch is hardened. |
| **Conditional HTTP Caching (Weak ETag)** | Deliberate | `apps/api/src/common/http-cache.ts`, `apps/api/src/app.factory.ts` | Cuts redundant payload transfers on public catalog/search/recommendation GETs (`W/"..."` + `304`, `max-age=30`) while enforcing `no-store` on `/favorites`, `/auth`, `/me`, `/admin`. | **Effective.** Minor HTTP spec limitation: `ifNoneMatch.trim() === etag` does not parse comma-separated ETag lists or `*`. | Hash computed over serialized payload per request (fast for small catalog JSON responses). |
| **Keyset (Cursor) Pagination & Disjunctive Faceting** | Deliberate | `apps/api/src/modules/catalog/catalog-query.ts`, `catalog-filters.ts`, `catalog.service.ts` | Provides stable pagination under concurrent catalog updates (currency-scoped cursor) and accurate multi-select facet counts without hiding sibling options (`ADR-0017`, `ADR-0018`). | **Solid.** Eliminates offset drift and keeps filter counts intuitive. | Cannot jump directly to arbitrary page N; requires `FacetsDTO` root-count summation for total display on PLP. |
| **Pure Domain Rule Engine** | Deliberate | `apps/api/src/modules/recommendations/relations-rules.ts` | Keeps rule-based related/upsell scoring, round-robin cross-sell category diversity, and manual-before-auto sorting pure and framework-free. | **Clean & Well-Tested.** Covered directly by fast unit tests (`relations-rules.test.ts`) with zero DB/Nest dependencies. | Must stay synchronized with SQL pre-filtering bounds in `CatalogService`. |

## 3. Cross-Cutting & Contract Patterns (`packages/*` & Monorepo)

| Pattern | Status | Location | Problem Solved | Assessment | Trade-offs |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Strict-Server / Tolerant-Client Schema Duality** | Deliberate | `packages/contracts/src/{catalog,search,recommendations}/{public,client}.ts`, `apps/api/src/common/parse-response.ts`, `apps/storefront/src/infrastructure/http/httpClient.ts` | Fails closed on server DTO leaks (`.strict()`) while allowing additive API fields without breaking deployed browsers (`.strip()`) (`ADR-0008`, `ADR-0017`). | **Signature strength of the repo.** Note gaps: `identity` has no `.strip()` client schemas yet, and `searchIndexDocumentSchema` (internal) is exported in the public root barrel. | Manual schema duplication between `public.ts` and `client.ts` increases maintenance when DTOs change. |
| **Fail-Fast Boot Env Validation** | Deliberate | `apps/api/src/config/env.ts`, `apps/storefront/src/config/env.ts` | Rejects missing/malformed env vars and unsafe production defaults (`COOKIE_SECURE=false`, dev secrets, `CHAOS_ENABLED=true`) before serving traffic. | **Strong & Verified.** Tested in unit tests on both backend and storefront. | Requires keeping `.env.example`, `infra/compose.yaml`, and Zod schemas aligned. |
| **Dual-Implementation Contract Test Suite** | Deliberate | `apps/storefront/src/infrastructure/repositories/productRepositoryContract.test.ts` | Verifies behavioral parity between `MockProductRepository` and `HttpProductRepository` (routed through `HttpClient` + `.strip()` schemas). | **High leverage.** Prevents test mocks from silently diverging from HTTP client parsing/serialization. | Does not run against live NestJS controllers (backend integration specs cover the server side separately). |
| **Build-Time Tree-Shaken Chaos Injection** | Deliberate | `apps/storefront/src/infrastructure/http/chaos.ts`, `apps/api/src/common/chaos.middleware.ts`, `apps/storefront/src/components/ApiDebugFab/ApiDebugFab.tsx` | Enables controlled latency and error testing in DEV/Playwright metrics with zero chaos code in production bundles (`docs/chaos-dev-guide.md`). | **Well-engineered.** API refuses boot if `NODE_ENV=production` and `CHAOS_ENABLED=true`; storefront verifies zero `x-chaos-*` strings in `dist/`. | Relies on Vite `import.meta.env.DEV`; will need a framework-agnostic guard if shared with Next.js. |

## 4. Notable Pattern Absences & Conscious Non-Adoptions

| Pattern | Current State | Rationale / Action |
| :--- | :--- | :--- |
| **React Error Boundaries** | **Missing (Gap)** | Zero `ErrorBoundary` components exist (including around lazy `<Suspense><SearchResultsPage /></Suspense>`). High-priority fix planned in the alignment phase. |
| **Compound Components & Render Slots** | **Deferred** | Current components (`Dropdown`, `MiniCart`, `RecommendationCarousel`, PDP Tabs) are prop-driven monoliths. Intentionally deferred until Phase 8 Design System extraction (`@minieshop/ui`). |
| **Separate Frontend Domain Entity Model** | **Conscious Simplification** | Storefront consumes `@minieshop/contracts` DTOs directly rather than mapping DTO → Entity → ViewModel. Appropriate at current complexity; revisit only if UI models diverge heavily from API shapes. |
| **Dedicated Message Broker / Redis** | **Conscious Non-Adoption** | Replaced by PostgreSQL `platform.outbox` (`ADR-0012`) and `InMemoryRateLimiter` (`ADR-0014`) to keep local infra minimal and zero-cost until multi-replica scale demands it. |

## 5. Pattern Maintenance Checklist ("As We Go")

Before merging any feature, refactor, or ADR change, verify:
1. **New pattern introduced?** Add a row with status, exact file paths, problem solved, honest assessment, and trade-offs.
2. **Existing gap resolved?** (e.g., `ErrorBoundary` added, `MediaService` DB leak removed, `ProductCard` switched to `useCartActions`, `react-instantsearch` kept/replaced) — update the corresponding row immediately.
3. **Pattern retired?** Remove or mark it as retired so this file always reflects live repository reality rather than historical intent.
4. **ADR created or superseded?** Cross-reference the ADR number in the row description.
